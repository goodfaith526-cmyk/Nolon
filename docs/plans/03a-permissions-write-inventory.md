# ملحق 03a: جرد مداخل الكتابة (F114-1، F114-4)

**المصدر:** الكود الحالي (أُعيد توليده مع P-2/P-3، ومعه مسارات `access-control` و`branch-access`). مُولَّد من شجرة TypeScript (AST) لكل `class` عليه `@Controller` ولكل method عليها `@Post/@Patch/@Put/@Delete`: البادئة من `@Controller` نفس الـ class (الملف الواحد قد يحمل عدة controllers، مثل `billing.controller.ts`)، واسم المعالج هو اسم الـ method (ما دوال `FileInterceptor` داخل `@UseInterceptors`). لا تصادم في المفتاح `الفعل + المسار`. القائمة سطر لكل مسار، مرتبة بالمسار ثم الفعل، بلا أرقام صفوف ولا عدد ولا أعمدة مصفوفة: تغييران يضيف كل منهما مساراً يلمسان سطرين مختلفين، فلا يتعارضان عند الدمج. لإعادة كتابة القائمة من الكود: `UPDATE_03A=1 pnpm exec vitest run src/access-control/write-inventory.spec.ts` داخل `apps/api`، ثم راجع الفرق. المسارات بدون البادئة العامة `/api/v1`.

**في P-1 (منفّذ):** الجرد بوابة. الاختبار `apps/api/src/access-control/write-inventory.spec.ts` يبني نفس القائمة من الـ AST ويطابقه مع هذا الملف **في الاتجاهين** بالمفتاح `الفعل + المسار + Controller.handler`، ومعه الملف والصلاحيات (مسار في الكود بلا سطر هنا = فشل؛ سطر هنا بلا مسار = فشل؛ مفتاح مكرر = فشل؛ ترتيب خاطئ = فشل)، مع fixture لملف فيه عدة controllers ولمسار رفع ملف.

**القفل لكل صف، بنية لا موضعاً:** بدل وضع `AccessTx.run` يدوياً في كل خدمة، `PrismaService` نفسه يأخذ قفل `access_state FOR SHARE` أول كل معاملة تفاعلية لطلب مسجَّل، ويلفّ كل كتابة مباشرة خارج معاملة (`prisma.x.create/update/upsert/delete...`) في معاملة تأخذ نفس القفل؛ ومعاملات الدُفعة (`$transaction([...])`) مرفوضة داخل الطلبات. لذلك كل صف أدناه يمر بالقفل بلا استثناء، والمسارات العامة (تسجيل الدخول، رموز المساعد) بلا نسخة وصول فلا قفل. تغييرات الصلاحية (حسابات المستخدمين الآن، وشاشات P-2/P-3 لاحقاً) تمر بـ `changeAccess`: `FOR UPDATE` أولاً، إعادة فحص المنفّذ تحت القفل، ثم رفع النسخة.

**الفرع لكل صف:** الحارس يضيّق `allowedBranchIds` إلى الفروع التي تملك **كل** صلاحيات المسار، فكل فحص فرع قائم في الخدمات (`assertBranchAccess`، `branchScope`، فرع الصف، الفروع المشاركة للشحنة) صار فحصاً لكل فرع تلقائياً. الفحوص الإضافية داخل الخدمات (صلاحية ثانية على صف بعينه) تقرأ فرع الصف نفسه (`access.has(p, row.branchId)`، و`holdsOnShipment` للشحنة وفروعها المشاركة). الوحدات العامة (`master_data`، `fx_rates`، `alert_settings`، `users`) بلا فرع. `—` = مسار بلا `@RequirePermission` (تسجيل الدخول، الحساب الشخصي، مسودات المستخدم نفسه...).
